## Issues Found

### ❌ Q14 — Math worker rejects RAG output as expression (BUG)
**Root cause:** Router generated a plan where `{{step_0.result}}` (full RAG text) was passed as the arithmetic expression to the math worker. The safe-expression regex `/^[\d\s+\-*/().]+$/` correctly rejects it — but the router should have extracted numeric values first (e.g. via a separate LLM step or by not chaining RAG→math directly).

**Impact:** Any query that asks to compute a percentage or arithmetic on product prices without an intermediate extraction step will fail.

**Workaround:** Ask in two separate queries, or rephrase: *"The Tesla costs 370,000 ILS and the MacBook costs 7,400 ILS. What is 15% of the difference in CHF?"* — the router will generate `[math, exchange]` with literal numbers.

### ⚠️ Q10 — Recommend without RAG
**Root cause:** Router routed "recommend" intent to `chat` only. The generalChat worker has no product knowledge — it gave a generic answer. Ideally the router would include `getProductInformation` before `chat` for recommendation queries.

### ⚠️ Q11 — Session history "that product" not resolved
**Root cause:** The `generalChat` worker (rule-based) received "The user wants to know how much the product would cost in US dollars, but doesn't specify which product" — it couldn't resolve the pronoun from session history. The synthesizer recovered by listing all products, but the answer lacked precision.
